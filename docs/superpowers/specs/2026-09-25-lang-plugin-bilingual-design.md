# 外语插件 · 日语配音 + 中文字幕 —— 设计

状态:**已实现**(2026-09-25,代码未提交 —— 视觉小说和插件的代码整体都还没进仓库)。日语声音经后端实测能合成;视觉小说里边读边念还没实测
日期:2026-09-25

## 和设计的出入(实现后补)

- 三个日语声音的档案名用半角括号:「未花(日语)」「知更鸟(日语)」「诺亚(日语)」。**诺亚由另一个会话导入**(它在做生盐诺亚的卡,按诺亚自己的立绘表情名配参考,再把 Wikira 的 17 个表情名挂成别名);这边只导入了未花和知更鸟
- 未花的 wiki 原声只够配 14 种表情,慌张 / 心虚 / 哭 分别挂在 害羞 / 惊讶 / 委屈 的别名上;知更鸟配了 16 种,病娇挂在坏笑上。每种用的原声记在 `docs/voice-server.md`
- 实测(真实模型 deepseek-v4-pro + 新预设):一条回复 45 句,日语全部配上;流式时日语先出、中文跟着出;历史、窄屏(390 宽)正常;开场白 105 句里 101 句配上,没配上的是原开场白自带的 `<生成例子>` 包裹行、注释行和一行「n」
- 语音:台式机 15:49、15:53 两次蓝屏(0x1000007E,和 GSV 无关的老问题),第二次正好在切权重时,把 `tts_infer.yaml` 写坏了,GSV 之后起不来。台式机会话修好后实测:未花、知更鸟的日语声音都能经 AnimaVN 合成,每句约 1 秒,情绪和别名都选对了(详见 `docs/voice-server.md`)
- 实测发现一个原来就有的问题(不是这次引入的):预设里「Lj要加入剧情」让模型也写 Lj 的台词,但台词前不写「Lj：」,切句时这些台词默认算 Wikira 的 —— 名牌显示 Wikira,开了语音也会用 Wikira 的声音念

## 背景

给 Wikira 挑声线时试听了中文和日语两版,用户觉得日语好很多(原因见 `docs/voice-server.md`「Wikira 声线候选」一节)。所以要做「日语配音、中文字幕」:屏幕上看中文,角色念日语。

原来的语音设计(`2026-09-24-vn-voice-design.md`)把这件事列在「之后再聊」。前端按句请求合成、情绪跟着立绘走,这些都不变;缺的只是「每句中文对应的日语从哪来」。

## 已确认的决策

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| 1 | 日语从哪来 | **主模型自己写**,不另调翻译模型 | 用户要求;保留「先写日语再翻译」的文风 |
| 2 | 哪些内容写日语 | 旁白和台词**都写**,日语在前、中文在后 | 用户要求「都先写」,并且要能看到日语 |
| 3 | 输出格式 | **一行日语,紧接着下一行是它的中文**,不加任何标签 | 用户要求「上一句日文下一句中文,我们自己处理 output」。相邻就是配对,不用事后对齐;也不增加标签负担 |
| 4 | 做成什么 | 一个新插件「外语」,和立绘 / 背景 / 音乐 / 语音并列 | 用户希望在插件里控制怎么写;插件块跟着插件模板同步,开关按预设各自管,和其他插件同一套 |
| 5 | 怎么认出日语 | 带假名的行是日语;下面紧跟的那行是它的中文 | 中文不会出现假名。提示词里要求中文行不夹假名 |
| 6 | 显示 | 视觉小说里日语小字在上、中文正常字号在下;插件里可以关 | 用户要求 |
| 7 | 念哪种 | 看**主声音(以及其他声音)的 `text_lang`**:`ja` 念日语,`zh` 念中文 | 不加新开关;声音本身知道自己是什么语言 |
| 8 | 缺日语时 | 日语声音遇到没有日语的句子**不念**,控制台记「缺日语」 | 不拿中文硬塞给日语模型 |
| 9 | 历史 | 日中两种原样发给模型 | 模型从历史里就能看到格式,保持一致 |
| 10 | 角色卡 | 复制 Wikira,**名字不改**,加「日语配音」标签区分 | 卡名会通过 `{{char}}` 进提示词、也用来认说话人;改名会让模型在正文里写出「Wikira(日语)」 |
| 11 | 声音 | 导入 诺亚 / 未花 / 知更鸟 三个日语声音,日语卡默认绑「未花(日语)」 | 用户选的这三个;未花和立绘是同一个角色。换声线由另一个会话在视觉小说菜单里做(改的就是卡的主声音) |

## 输出格式

```
<sprite:坏笑>
「エルジェイ様、さっきのドヤ顔、ぜんぜん隠せてなかったよ？」
「Lj sama 刚才那副得意的样子，一点都没藏住哦？」

彼女はくすっと笑って、指先で彼の頬をつついた。
她轻笑一声，用指尖戳了戳他的脸颊。
```

- 每段先写一行日语,下一行写这段的中文。台词单独成行,日语和中文都用「」
- 立绘 / 场景 / 音乐标签写在这一对前面(写在日语行开头也认)
- 日语行里不写标签;中文行里不夹假名

## 插件

### 配置(`app_settings` 的 `plugin.lang`)

| 字段 | 默认 | 说明 |
|---|---|---|
| `blockPrompt` | 见下 | 「加入当前预设」时写进块里的内容;预设里的这块始终跟着它同步(`syncPluginBlocks`) |
| `showJa` | true | 视觉小说里显示日语 |

没有「标签格式」:这个插件不用标签。

插件块:identifier `anima_lang`,名字「外语指令 · 插件」,加入 `PLUGIN_BLOCK_IDS`(插在已有插件块后面,几块挨在一起)。

默认提示词:

```
[双语输出]
这是日语配音、中文字幕的视觉小说。整条回复(旁白和台词)都要日中对照着写:
- 每一段先写一行日语,紧接着下一行写这段的中文。一行日语对应一行中文,先日后中。
- 台词单独成行,日语和中文都用「」括起来。
- 中文以日语为参考来写:保留一点翻译腔,同时通顺、自然、优美。
- 中文里不要夹杂假名;日语那一行不要写任何标签。
- 立绘、场景、音乐标签写在这一对(日语 + 中文)的前面。

示例:
<sprite:微笑>
「おかえり。今日も一日、お疲れさま。」
「欢迎回来。今天也辛苦啦。」

彼女はそう言って、ソファの端に寄って場所を空けた。
她说着,往沙发边上挪了挪,给他让出位置。
```

示例里的 `<sprite:微笑>` 是写死的示例,用户改了立绘标签格式时要自己改这里(和其他插件的提示词一样由用户维护)。

### 界面

插件抽屉加一页「外语」,界面单独放 `components/LangPanel.tsx`。插件抽屉同时嵌在视觉小说菜单的「插件」页里(另一个会话做的 `renderPluginsDrawer`),所以两边都会出现。

- 说明:这个插件做什么、格式长什么样
- 这块在当前预设里的状态 + 「加入当前预设」(和立绘插件同一个 `pluginBlockState` / `insertPluginBlock`)
- 提示词模板编辑框 + 恢复默认
- 「视觉小说里显示日语」开关

## 解析(`plugins/lang.ts`,纯函数)

### 认日语行

- 按换行分行;每行先用 `extractTags` 摘掉立绘 / 背景 / 音乐标签,剩下的叫「正文」
- 正文里有平假名或片假名(不算「・」)→ 日语行
- 兜底:正文没有假名,但下一行正文和它一字不差(比如「……」「……」、全是汉字的短句写了两遍)→ 前一行也当日语
- 一条回复里一行日语都没有 → 完全照旧(旧聊天、别的卡、不开插件的预设)

### 挂到中文上

- 日语行从正文里摘掉,**行里的标签留在原位**(标签写在日语行开头时,仍然作用到下面的中文)
- 日语挂在它下面紧跟的那一行中文上;那行中文切出来的第一句带着它(`VNLine.ja`)
- 日语行后面紧跟的还是日语行、或者整条回复结束(不在流式中)→ 这行日语没有中文,**当正文显示**(`VNLine.text` = 日语,标记 `jaOnly`),不至于内容丢掉
- 摘掉日语后,中文照原来的 `parseReply` 切句、认标签,规则一条不改

### 位置换算

`parseReply` 返回的 `ends`(每句在原文里结束的位置)用来插话截断。摘掉日语行后要把位置换算回原文:记下每段保留下来的内容在原文里的起点,按段换算。日中是交替写的,截到第 i 句中文结束处,后面的日语自然一起截掉。

### 流式

- 最后一行还没写完:
  - 它有假名 → 是正在写的日语。追加一句「中文还没开始」的句子(`text` 空,`ja` = 已写出的日语),对话框里先显示日语小字;中文开始后同一句接着显示中文(句子序号不变)
  - 没有假名 → 按中文处理,和现在一样
- 最后一句还在写时不念(原规则)

## 显示

- 对话框:`ja` 有值且 `showJa` 开着 → 文字上方一行小字(约 0.72 倍字号、颜色淡),中文照原来的打字效果
- 历史回看:每句同样日语小字在上;「显示原文」照旧显示原始输出
- 聊天界面、存档缩略图:不改(缩略图只取中文)
- 窄屏:日语跟着对话框字号缩小,对话框高度随内容撑开,实测不溢出

## 语音

`planVoiceLines` 取文字的规则改成(`speechText(line, lang)`,放在 `plugins/lang.ts`):

| 声音语言 | 这句有 `ja` | 这句是 `jaOnly` | 普通中文句 |
|---|---|---|---|
| `ja` | 念 `ja` | 念 `text`(本来就是日语) | 不念,控制台「缺日语」 |
| 其他 | 念 `text`(中文) | 不念 | 念 `text` |

- 情绪照旧:这句生效的立绘表情(标签作用在中文那句上)
- 取到的文字照旧过 `cleanSpeech`(去引号、括号动作、星号)
- 缓存键里本来就有文字,中文版和日语版不会混
- 控制台这句的语音记录显示实际送去合成的文字;没念的写原因

## 验证

前端没有测试框架(和语音设计一样):规则都写成 `plugins/lang.ts` 里的纯函数,验证靠 `npm run build`、`npm run lint` 和浏览器里实际跑。

浏览器实测(日语卡 + 新预设,真实模型):
- 流式时日语小字先出、中文跟着出;Wikira 的台词念日语,情绪跟立绘走
- 缺日语的句子不念,控制台有记录
- 关掉「显示日语」只剩中文
- 历史回看、插话截断正常
- 窄屏下对话框不溢出
- 换成诺亚、知更鸟也能念
- 旧的 Wikira 卡、旧聊天完全不受影响

实测前备份各插件的现有设置,只新增 `plugin.lang`,不点「恢复默认」;测试发的对话测完问用户要不要删。
