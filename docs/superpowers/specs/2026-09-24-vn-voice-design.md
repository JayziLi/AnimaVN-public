# 视觉小说 · 语音（GPT-SoVITS）—— 设计

状态:**已实现**(2026-09-24,未提交)。实现和本文的出入见实施计划 `docs/superpowers/plans/2026-09-24-vn-voice.md` 开头的表
日期:2026-09-24

## 背景

立绘、背景、BGM 三个插件已经跑通,下一步是角色语音。要求:尽量贴合角色声线,能接不同的语音引擎。

参考了两个项目:
- **SillyTavern 的 TTS 扩展**:每个引擎实现同一组接口(合成 / 列出声音 / 检查连接),用一张「角色名 → 声音」表选声音。没有逐句情绪
- **LingChat**:`generate_voice(text, emo)`,情绪传给每个引擎,不支持的忽略;GPT-SoVITS 适配器按需加载权重、请求串行加锁、失败重试一次;连续失败 3 次熔断。它要求 AI 写 `【情绪】` 再用分类模型纠正,我们不需要 —— 立绘标签已经给出了情绪

引擎选 GPT-SoVITS:用角色自己的语音微调过的模型,音色最像;中文社区有大量现成的角色模型。
它跑在用户的另一台 RTX 5090 台式机上,两台电脑的情况、SSH、实测数据见 `docs/voice-server.md`。

## 已确认的决策

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| 1 | 引擎在哪 | 5090 台式机上的 GPT-SoVITS api_v2,AnimaVN 后端调它的 HTTP 接口 | 用户说「直接把我的 5090 当服务器,调接口返回声音」 |
| 2 | 素材在哪 | 模型权重、参考音频都放在 5090 上;AnimaVN 只存它们在 5090 上的**路径**和参考原文 | api_v2 的 `ref_audio_path` 只认服务端本地路径,没有上传接口;SillyTavern / LingChat 也是这样做 |
| 3 | 模型来源 | 先用社区训练好的现成模型(阿米娅、琴柳,v4),不自己训练 | 用户要求 |
| 4 | 语言 | 中文 | 用户要求 |
| 5 | 念哪些 | 只念有说话人、且说话人对得上声音的台词;旁白和用户的话不念 | 用户要求旁白不念 |
| 6 | 情绪从哪来 | 这句生效的**立绘表情名** → 情绪表同名 / 别名那行 → 否则默认。不加新标签、不加提示词块 | AI 已经在写立绘标签;语音零提示词成本 |
| 7 | 谁请求合成 | 视觉小说界面按句请求,后端转发并缓存 | 切句本来就在前端(`vn/script.ts`);LingChat 那种后端流水线要把切句在 Python 里重写一遍 |
| 8 | 缓存 | 必须缓存,存 SQLite BLOB | GPT-SoVITS 每次请求随机种子不同,同一句重算语气会变;回看、重播要听到同一段 |
| 9 | 文字和语音的时机 | 插件设置里的开关:**不等**(默认)/ 等语音 | 起初默认等语音;2026-09-24 用户改成默认不等:文字直接出,文字后面转圈表示语音还在合成 |
| 10 | 引擎接口 | 按引擎抽象,先只实现 GPT-SoVITS | 用户要能接不同 API;YAGNI,其他引擎等真要接时再写 |

## 实测约束(2026-09-24,5090,v4 模型)

| 项目 | 数值 | 对设计的影响 |
|---|---|---|
| 合成约 20 字一句 | 64 步 1.7–2.7 秒(32 步 1.2–1.8 秒);12–17 秒的长句 64 步要 7–7.6 秒。一句里按标点切开的几段一起合成(`batch_size`)后:短句约 1 秒,15 秒的长句 2.3 秒 | 要预合成,念当前句时合成后面的;默认「等语音」 |
| 切换角色 | 1.7–2.2 秒 | 记住已加载的权重,只在换人时切 |
| 启动后第一次合成 | 37 秒 | 要预热;第一次请求超时 90 秒 |
| 同时来两个请求 | 服务端排队 | 同一个连接串行,切权重和合成必须在一把锁里 |
| 参考音频 | 必须 3–10 秒;3 秒左右的短参考电子音明显,换 7 秒的原声后频谱最接近原声、耗时不变 | 录入时提示「推荐 5–10 秒」;报错原样显示 |
| 采样步数 | 频谱指标上 64 / 128 步和 32 步差不多,但用户试听长参考 + 64 步最好,耗时约 32 步的 1.5 倍 | 默认 64,连接上可改 |
| 切权重的副作用 | api_v2 会把最后加载的权重写回 `tts_infer.yaml`,重启后默认加载它 | 只有 AnimaVN 切权重时,「当前权重」的记录重启后仍然对;预热时强制重新切,作为手动纠正的办法 |
| 报错格式 | 400 + `{"message":"tts failed","Exception":"<原因>"}` | 原因原样透传给界面 |
| 只有标点的文本 | 400「请输入有效文本」 | 前端先过滤,不发请求 |

## 结构

后端:
- `app/tts/base.py` —— 引擎接口:`synthesize(text, voice, emotion) -> (bytes, mime)`、`warmup(...)`,以及 `TTSError`
- `app/tts/gpt_sovits.py` —— api_v2 适配器:每个连接一把 `asyncio.Lock`;记住当前加载的 GPT / SoVITS 权重,变了才调 `set_gpt_weights` / `set_sovits_weights`;记住是否预热过;连不上或出错时清掉这些记录
- `app/tts/registry.py` —— 按连接的 `api_type` 取适配器
- `app/tts/http.py` —— TTS 用的 httpx 客户端。目标是回环、私有网段或 100.64.0.0/10(Tailscale)时**不走代理**(`trust_env=False`),其他地址照常
- `app/tts/cache.py` —— 缓存读写和淘汰
- `app/api/tts.py` —— 连接的增删改查、测试、预热;`/api/tts/speak`;缓存统计 / 清空
- `app/api/voices.py` —— 声音档案、情绪表、卡的绑定

前端:
- `debug/plugins/voice.ts` —— 纯函数:插件配置、清理台词、判断该不该念、说话人 → 声音、参考文件名解析、`refs.json` 解析
- `debug/plugins/useVoicePlugin.ts` —— 调试台里的语音状态(连接、档案、当前卡的绑定)
- `debug/components/VoicePanel.tsx` —— 插件抽屉的「语音」页。`PluginsDrawer.tsx` 已经 1400 多行,这一页单独成文件
- `debug/vn/voice.ts` —— 语音播放器单例:请求队列、解码、播放、压低 BGM
- `debug/vn/bgm.ts` —— 暴露共用的 AudioContext 和「压低 / 恢复」接口
- `debug/vn/VNScreen.tsx` —— 等语音、预合成、翻页停止、历史重播、控制台里的语音状态

## 数据

- `tts_connections`:id、name、api_type(目前只有 `gpt_sovits`)、base_url、sample_steps(默认 64)、options(JSON,留给以后的引擎)、created_at
- `voice_profiles`:id、name(唯一)、aliases、connection_id、gpt_weights、sovits_weights(5090 上的绝对路径)、text_lang(默认 `zh`)、speed(默认 1.0)、updated_at
- `voice_emotions`:id、profile_id、label、aliases、ref_path(5090 上的绝对路径)、prompt_text、prompt_lang、sort(排第一的是默认)
- `card_voices`:card_id、profile_id、is_main。每张卡最多一个主声音。删卡时删绑定,复制卡时复制绑定,删档案时删它的全部绑定
- 删连接时如果还有档案在用,拒绝删除(400「还有 N 个声音档案在用这个连接」)
- `tts_cache`:key(sha256)、data(BLOB,deferred)、mime、size、created_at、last_used_at

名字规则和立绘一样:同一个档案里情绪的名字 / 别名不能撞,不能带 `<>[]{}【】「」` 和换行。
新表靠启动时的 `create_all` 建,不用写迁移脚本。

## 规则

### 哪句念、用哪个声音、什么情绪

1. 这句没有说话人(旁白)→ 不念
2. 说话人是这张卡的角色名(`script.ts` 没认出「名字：」时用的就是它)→ 主声音;否则按名字 / 别名(不分大小写)在这张卡绑定的其他声音里找,找不到 → 不念
3. 清理台词:去掉全角 / 半角括号里的动作、`*`、各种引号;清理后没有文字(只剩标点和空白)→ 不念
4. 情绪:主声音用这句生效的立绘表情名(和立绘层的算法一样:从第一条回复累计到这句);其他声音不传情绪
5. 后端解析情绪:label 或 aliases 匹配(不分大小写)→ 那一行;匹配不到或没传 → 排第一的那行。档案一行情绪都没有 → 报错「这个声音还没有参考音频」

### 合成请求(`POST /api/tts/speak`)

请求体 `{profile_id, emotion, text}`,返回 `audio/wav`,响应头 `X-TTS-Cache: hit|miss`,以及实际用的情绪名 `X-TTS-Emotion`(URL 编码)。
开发时前端(5173)和后端(8000)不同源,这两个头要加进 CORS 的 `expose_headers`,不然前端读不到。

- 缓存键 = sha256(权重路径 + 发给 api_v2 的请求体,不含 seed)。档案或情绪行一改,键自然就变了
- 未命中:拿连接的锁 → 权重不同就先切 → 合成 → 写缓存。第一次请求(没预热过)超时 90 秒,之后 30 秒
- 请求体固定 `text_lang`、`prompt_lang`、`media_type: wav`、`text_split_method: cut5`、`sample_steps`(连接上的值)、`speed_factor`(档案上的值)
- `prompt_lang` 按参考原文判断:有假名 → `ja`,否则 `zh`(LingChat 的做法)
- 缓存总量超过 500 MB 时,按 last_used_at 删最旧的

报错:

| 情况 | 后端返回 |
|---|---|
| api_v2 返回 400 | 502,`detail` = 它的 `Exception` 原文 |
| 连不上 | 503「连不上语音服务 <地址>」,并清掉权重 / 预热记录 |
| 超时 | 504「语音合成超时」 |
| 档案 / 情绪配置问题 | 400 / 404,中文说明 |

### 预热

`POST /api/tts/connections/{id}/warmup {profile_id}`:先清掉这个连接的「当前权重」记录、强制切到这个档案的权重,再用它的默认情绪合成一句「你好。」,不进缓存。
进入视觉小说界面时,如果语音开着、这张卡有主声音,前端在后台调一次。插件页也有「预热」按钮。

### 播放

- 预合成:当前句 + 这条回复后面所有要念的台词(不念的句子不算;原来只排后面 2 句,点得快时追不上,2026-09-24 改成整条)。流式时,一句写完(后面出现了下一句)就排进去。前端同一时刻只发一个请求(反正服务端也是串行),当前句优先;跳到别的回复时丢掉还没发出的请求,已经发出的照常完成、进缓存
- **等语音**:翻到一句要念的台词时,语音没好就先不开始打字,好了文字和声音一起开始;最多等 3 秒,超时先出文字,语音好了再补上
- **不等**(默认):文字立刻开始,语音还在合成时文字后面转一个小圈,好了就放、圈消失
- 翻页、跳转、退出视觉小说时立刻停掉当前语音
- 和 BGM 共用一个 AudioContext(iOS 只需解锁一次)。念台词时 BGM 淡到原音量的 35%,念完 0.5 秒淡回
- 连续 3 句失败 → 这次进入视觉小说期间停用语音,顶栏提示「语音服务连不上」,点一下重试(重置计数并预热)

### 插件配置(app_settings,键 `plugin.voice`)

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 总开关 |
| `waitForVoice` | false | 等语音 / 不等 |
| `maxWaitSec` | 3 | 等语音最多等几秒 |

语音音量和静音按设备记在 localStorage,和 BGM 的放在一起。

视觉小说的局内设置(菜单 → 设置 → 声音)里也能改上面三项(同一份配置),另外三项是视觉小说自己的偏好,按设备记住(`anima.vn.settings`):

| 字段 | 默认 | 说明 |
|---|---|---|
| `voiceInterrupt` | true | 翻页时:停止语音 / 念完为止(这句的语音一开始自然换掉上一句;跳过时照样停) |
| `autoWaitVoice` | true | 自动播放:等这句的语音合成完、念完再翻 / 不等 |
| `duckLevel` | 0.35 | 念台词时 BGM 压到原音量的多少:不压低 1 / 压低一点 0.6 / 压低 0.35 / 几乎听不见 0.12 |

## 界面

- 插件抽屉:立绘 | 背景 | BGM | **语音**
  - 设置:总开关、等语音 / 不等、最多等几秒
  - 连接:地址(开发时经 SSH 隧道就是 `http://127.0.0.1:9880`)、采样步数、测试、预热
  - 声音档案:列表;展开是权重路径、语速和情绪表。情绪表每行:名字、别名、参考路径、原文、试听。粘贴路径时,文件名是 `【情绪】原文.wav` 就自动填名字和原文。可以粘贴 `refs.json`(格式见部署文档)一次导入一个角色
  - 这张卡:主声音选哪个,其他声音加哪几个;并提示这张卡的立绘表情里哪些还没有对应的情绪(没有就用默认)
- 视觉小说:
  - 顶栏音量弹窗分「音乐」「语音」两条,各自可以静音
  - 等语音时对话框里显示一个小的「……」
  - 对话框底边最左、历史里每句要念的台词后面,各有两颗按钮:重播(命中缓存,不重新合成)、重新生成(`fresh`:不看缓存再合成一遍,api_v2 每次随机种子不同所以念法会变,新的替换缓存里的旧版)。历史里 AI 回复按画面上的句子一句一句列;重播按钮的提示里写着实际用了哪个情绪的参考
  - 控制台:每句的说话人 → 声音、请求的情绪 → 实际用的情绪、缓存命中、耗时、错误

## 测试

- 后端(pytest):用 `httpx.MockTransport` 假装 api_v2,和 `tests/test_anthropic_provider.py` 同一个写法
  - 同一个档案连续合成只切一次权重;换档案才切;出错后下一次重新切

  - 私有地址不走代理
- 前端没有测试框架:规则都写成 `plugins/voice.ts` 里的纯函数,验证靠 `npm run build`、`npm run lint` 和浏览器里实际跑一遍(阿米娅、琴柳两张卡)
