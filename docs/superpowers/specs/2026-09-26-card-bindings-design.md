# 角色卡绑定玩家身份和预设

状态：已实现（2026-09-26）

## 目标

用户原话："给角色卡添加一个绑定的功能：绑定玩家身份，绑定预设。"

在这之前：
- 人设（玩家身份）已经能绑卡，但入口只在人设抽屉的人设详情里，从卡上看不出绑了谁。
- 预设不能绑。全局一个「当前预设」，每条对话记着当时用的预设，打开旧对话会恢复。所以新卡、新对话沿用上一张卡的预设。比如芳乃和茉子都有专用预设，最近一次对话用的却是「默认预设」。

## 已定的决定

| 项 | 决定 |
|---|---|
| 入口 | 三处，改的是同一份数据：①角色卡编辑器头像下面新加「绑定」一栏，玩家身份、预设各一个下拉，一眼看到、直接改；②人设抽屉原有的「绑定到当前角色卡」勾选保留；③预设面板的预设下拉下面加「绑定到当前角色卡「X」」勾选，试好了顺手绑。游戏菜单的「角色」「预设」页用的是同一套组件，游戏里同样能改 |
| 选卡时 | 绑了就换过去，人设和预设的提示合成一条：「人设换成了「方知宥」(这张卡绑定的)；预设换成了「阿米娅 DeepSeek」(这张卡绑定的)」 |
| 绑定 vs 对话记的预设 | 绑定优先：选卡、打开这张卡的任何一条对话，都用绑定的预设（用户选的）。代价是调试台打开旧对话不再自动恢复当时的预设，想复现要手动换 |
| 没绑预设的卡 | 保持原样：打开对话恢复那条对话记的预设，新对话沿用当前预设。不加「默认预设」（用户选的）。人设照旧：没绑的卡换回默认人设 |
| 临时换 | 玩着手动换预设 / 人设只对这次有效，不改绑定；下次选这张卡还是换回绑定的。预设面板这时勾选是空的，下面提示「这张卡绑的是「X」，现在临时用的这套；勾上就改绑成这套」 |
| 在卡编辑器里改绑定 | 当场生效：绑人设就启用它，解绑人设换回默认人设（和选卡时一样）；绑预设就换过去（有没保存的改动时先问，和手动切预设一样），解绑预设不动当前预设 |
| 有没保存的改动 | 选卡时绑定的预设和当前的不一样，但当前预设有没保存的改动：不换，提示「预设有没保存的改动，没换成这张卡绑定的「X」」 |
| 复制 / 删除 | 复制卡时两种绑定都跟着复制（以前复制卡不带人设绑定，一起补上）；删卡时清掉它的绑定；删预设时清掉指向它的绑定（删人设本来就会清） |

## 数据

- 都存在后端 `app_settings`，全局一份，不改表结构，不用迁移：
  - `persona.bindings`（已有）：`{default: 人设 id | null, cards: {卡 id: 人设 id}}`
  - `preset.bindings`（新）：`{cards: {卡 id: 预设 id}}`
- 前端：`frontend/src/debug/lib/presetBinding.ts`（新）；`lib/personaBinding.ts` 里的 `bindCard` 改成两种绑定通用；`components/CardBindings.tsx`（新）是卡编辑器里那一栏；`DebugApp.tsx` 的 `applyBoundPersona` / `applyBoundPreset` 在选卡（`selectCard`）和开对话（`loadChat`）时套用

## 修过的问题

- 2026-09-27：
  - 问题：切到绑了预设的卡时，`selectCard` 先换了预设，对话却要等两三次网络往返才换。这期间 `DebugApp` 的「卡 / 预设 / 用户名同步」（防抖 600ms）会把新卡绑定的预设写进上一张卡的对话，下次打开那张卡就恢复成别人的预设。手机网络下容易碰到
  - 修法：同步前判断 `metaRef` 里的卡和当前卡是不是同一张；不是（切卡途中）就先不写 `preset_id` / `user_name`，等对话换好再算
  - 由代码审查子 agent 发现，只做了 `tsc` 和 lint，没在浏览器里复现
  - 没改的一处：第一次选绑定卡时 `newChat` 拿的是闭包里的旧预设，新对话先记成旧的，600ms 后被同步改对
