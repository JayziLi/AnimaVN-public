状态:**已实现**(2026-09-25,未提交)。实现和本文的出入见实施计划 `docs/superpowers/plans/2026-09-25-sprite-emotion-matching.md` 开头的表
日期:2026-09-25
前置:立绘插件 `2026-09-23-vn-screen-sprite-plugin-design.md`;语音 `2026-09-24-vn-voice-design.md`、`2026-09-24-indextts-engine-design.md`

## 背景

- 现在的立绘标签只在「表情变了」时写,名字必须和卡上的立绘名一字不差,对不上就不切图。语音的情绪跟着立绘走,所以语气变化也很稀疏;用户试玩反馈语音「情绪没感觉」
- 参考了 LingChat(https://github.com/SlimeBoyOwO/LingChat):每句台词前都写【情绪】,再用 ONNX 分类模型把标签归一到固定的 19 类,立绘和语音都从这个情绪走
- 实测(2026-09-24,24 条手写例子,i9-13900H 单线程):
  - LingChat 的模型(6 层 BERT,19 类固定输出):自由标签命中 8/24,每次 61 毫秒,常驻 +69 MB。只能输出它自己的 19 个词,接不上每张卡各不相同的立绘名
  - bge-small-zh-v1.5 int8(句向量,和候选名字比相似度):命中 15/24,每次 2 毫秒,常驻 +24 MB。候选可以是任意名字
  - 两者把台词拼进去都不变好(bge 反而降到 9/24),所以只看标签
- 用户的取舍:**流畅、即插即用、不让玩家操心提示词**最重要,准确度次要(模型只是兜底)

## 已确认的决策

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| 1 | 标签写多密 | `{{char}}` 的**每句台词**前都写一个(LingChat 的做法),不再是「表情变了才写」 | 每句都有情绪,语音才有语气变化 |
| 2 | 提示词里给不给列表 | 给:`{{sprites}}` 列出这张卡的立绘差分,**但不限死**,没合适的可以写别的情绪词 | 模型会尽量往有的图上挑,大多直接命中;挑歪了有模型兜底 |
| 3 | 提示词写法 | 照搬 LingChat 的**标签规则和正误示范**(2~5 字、不写动作和主语),措辞改写。不搬它的回复格式(整条只有「【情绪】台词」、没有旁白、台词不带引号)和预设该管的内容 | 回复格式会和酒馆预设抢写法,也会让按引号认台词的切句失效。LingChat 是 AGPL,不逐字复制 |
| 4 | 对不上时 | 交给模型,输出这张卡**列表里最像的一个**,不设门槛 | 用户要求「让它输出列表里的内容」 |
| 5 | 没配立绘的卡 | 用一份内置基础表情列表(和 IndexTTS 默认向量表同一套名字)代替 `{{sprites}}`,照样每句写、照样匹配 | 从酒馆导入的卡大多没有立绘;语音照样能有语气 |
| 6 | 模型 | bge-small-zh-v1.5 int8(MIT,Xenova 转的 ONNX 版) | 候选名字任意、快、小;LingChat 的 19 类模型接不上每张卡自己的名字 |
| 7 | 在哪跑 | **后端**,前端先做精确匹配,对不上的才问后端 | 手机不用下模型;后端有 pytest |
| 8 | 模型不在 / 出错 | 退回现在的行为:对不上就保持当前立绘,控制台标红写原因 | 模型坏了不能让视觉小说坏掉 |

以下几条没有和用户逐条过,按上面的原则定的:

| # | 决策 | 结论 |
|---|---|---|
| 9 | NPC 台词前的标签 | 标签后面紧跟的是**另一个有名字的角色**的台词(`script.ts` 认出了「名字：」,且不是卡的角色名)→ 不切主角立绘。紧跟旁白照常生效(「<sprite:开心>她笑着说：「……」」这种写法标签落在旁白上) |
| 10 | 结果还没回来时 | 立绘先保持上一张,回来再切;语音**等结果回来再合成**(当成「这句还没写完」),免得用错的情绪合成进缓存 |
| 11 | 语音用哪个名字 | 匹配后的立绘名(或内置表情名),不是 AI 写的原词。语音按名字 / 别名找情绪行的规则不变 |
| 12 | 旧模板升级 | 存着的模板和旧版默认一字不差 → 读取时换成新版;改过的不动(插件页照常有「恢复默认模板」) |
| 13 | 模型状态 | 插件页立绘一栏显示一行模型状态,没装时写怎么装 |

## 提示词

标签格式不变(默认 `<sprite:{表情}>`,可改)。新的默认模板:

```
[立绘指令]
{{char}} 说的每一句话，都必须以 {{sprite_tag}} 开头，用来形容 {{char}} 说这句话时的心情。
从下面这些表情里选一个，作为每句话开头的表情：
{{sprites}}

表情务必简短，2~5 个字，比如「慌张」「难为情」。列表里实在没有合适的，也可以写一个别的情绪词。
绝对不要在标签里写动作或主语！只允许写表情。
旁白和其他角色说的话前面不用写。标签单独写，不要放进引号或括号里，也不要解释它。

{{sprite_examples}}
```

宏:
- `{{sprites}}`:这张卡有立绘 → 和现在一样,每行「- 名字：说明」;一张都没有 → 内置基础列表,每行「- 名字」
- `{{sprite_tag}}`:不变,`<sprite:表情名>`
- `{{sprite_examples}}`(新):正误示范,标签按当前格式生成:

```
正确的示范：
<sprite:高兴>「今天要不要一起吃蛋糕呀？」
<sprite:无语>「只是今天天气有点不好呢。」
她后退了两步。
<sprite:慌张>「被那种东西碰到的话，感觉浑身都不干净啦！」
错误的示范：
<sprite:我高兴地走过来>「今天要不要一起吃蛋糕呀？」
错误原因：标签里不能写动作或主语，必须简短。
```

### 内置基础表情

和 `app/tts/emotion_presets.py` 的 `PRESETS` 是同一张表:每组第一个词是名字,其余是别名。前端 `plugins/emotions.ts` 抄一份,两边注释互相指着。

平静、微笑、开心、温柔、认真、担心、难过、哭、惊讶、慌张、害羞、疑惑、生气、害怕、厌恶、忧郁

## 匹配

### 前端(`vn/`)

1. 每个立绘标签先精确匹配:候选的名字或别名,不分大小写(现有的 `resolveByLabel`)
2. 对不上的,收集起来**一次请求**问后端;结果按「候选签名 + 标签」缓存在内存里。候选签名 = 候选的 key、名字、别名拼起来,换卡、改立绘都会变,缓存自然作废
3. 候选:这张卡有立绘 → 每张立绘 `{key: id, names: [名字, ...别名]}`;没有 → 内置列表 `{key: 名字, names: [名字, ...别名]}`
4. 一个标签的状态:`exact`(精确命中)/ `model`(模型给的,带相似度)/ `pending`(在问)/ `failed`(模型不可用,带原因)

各层怎么用:

| | exact / model | pending | failed |
|---|---|---|---|
| 立绘层(有立绘) | 切到那张 | 保持上一张 | 保持上一张 |
| 占位框(没立绘) | 写匹配到的内置名 | 保持上一个 | 写 AI 的原词(现在的行为) |
| 语音(主声音) | 用匹配到的名字当情绪 | 这句先不合成 | 和立绘层 / 占位框一致 |

立绘层、语音、历史页的累计算法是同一个函数(`spriteLabelAfter`),多传一个「标签 → 结果」的查询函数。

### 后端

`POST /api/emotion/match`,不查库、不存状态:

```json
{
  "tags": ["有点心疼", "小得意"],
  "candidates": [{"key": "s1", "names": ["微笑", "smile"]}, {"key": "s2", "names": ["担心", "worried"]}]
}
```

- `tags` 1–50 个,`candidates` 1–200 个,每个候选 1–20 个名字;每个字符串去掉空白后 1–40 字。不合格 422
- 返回 `{"model": "bge-small-zh-v1.5", "results": [{"tag", "key", "name", "score"}]}`,顺序和 `tags` 一样;`name` 是相似度最高的那个名字,`score` 是余弦相似度(3 位小数)
- 相似度 = 标签向量和候选每个名字的向量的余弦,取最大。并列取候选里排前面的
- 模型不可用 → 503,`detail` 写原因(「情绪识别模型没装:<目录>」/ 加载报错原文)

`GET /api/emotion/status` → `{"ready": bool, "model": "bge-small-zh-v1.5", "detail": str | null}`。会顺带触发加载,所以装了但加载失败也能看出来。

实现:
- `app/emotion/encoder.py` —— `BgeEncoder`:`tokenizers` 读 `tokenizer.json`(截断到 64 个 token),`onnxruntime` 单线程跑 `model_quantized.onnx`,一批文本补齐到同一长度,取 CLS 向量再归一化
- `app/emotion/matcher.py` —— `EmotionMatcher(encoder)`:文本 → 向量的 LRU 缓存(4096 条),同一张卡的立绘名只算一次;排序逻辑。encoder 是协议,测试用假的
- `app/emotion/service.py` —— 进程里一个懒加载的单例:第一次用时加载,加锁;加载失败记下原因,下次请求再试
- `app/api/emotion.py` —— 两个接口,都写成同步函数:FastAPI 会放进线程池跑,推理不堵事件循环
- `app/config.py` —— `emotion_model_dir`,默认 `AnimaBackend/models/bge-small-zh-v1.5`,环境变量 `EMOTION_MODEL_DIR` 可改
- 依赖加 `onnxruntime`、`tokenizers`、`numpy`

### 模型文件

- `AnimaBackend/scripts/download_emotion_model.py [--dir DIR]`:下 `onnx/model_quantized.onnx` 和 `tokenizer.json`(Hugging Face `Xenova/bge-small-zh-v1.5`,失败换 `hf-mirror.com`),校验 SHA-256,先写临时文件再改名;已经有且哈希对就跳过
  - `model_quantized.onnx` `15b717c382bcb518ba457b93ea6850ede7f4f1cd8937454aa06972366cd19bcc`
  - `tokenizer.json` `48cea5d44424912a6fd1ea647bf4fe50b55ab8b1e5879c3275f80e339e8fae26`
- `AnimaBackend/models/` 进 `.gitignore`
- Docker:构建时跑下载脚本,放到 `/app/models/bge-small-zh-v1.5`,设 `EMOTION_MODEL_DIR`。**不能放 `/app/data`**,那是数据卷的挂载点
- `start.bat` 不自动下载(几十 MB,别让启动变慢);模型没装时插件页会提示

## 语音

- 主声音的情绪 = 这句生效的立绘名 / 内置表情名(匹配之后的)
- 后端找情绪行(`app/api/tts.py` 的 `pick_emotion`):名字 / 别名精确对上 → 那一行;对不上 → **就近回退**,用同一个 bge 模型在这个声音的情绪行里(名字 + 别名)挑最像的一行;模型没装或出错 → 排第一的(默认)。2026-09-25 和台式机会话商量后加的:素材已经补到头了(PRTS 每个角色只有 38 条中文语音),像琴柳没有「惊讶」这种,与其一律念成平静,不如用最接近的一段参考。想指定就给那一行加别名(比如琴柳【疑惑】加别名「惊讶」),精确匹配优先
- 没做:按情绪调语速(GSV v4 只能调参考、语速和采样参数)、同一情绪挂多段参考随机选、用 IndexTTS 生成缺的情绪参考 —— 等用户试玩后再说
- 「按立绘表情补齐」(`POST /api/voices/{id}/emotions/from-sprites`):这张卡**没有立绘**时改用内置基础列表,名字和别名都来自 `PRESETS`,向量照表预填 —— 这张表本来就覆盖了内置列表的每一项
- 插件页「这张卡的立绘表情里哪些还没有对应的情绪」:没有立绘时对照内置列表

## 界面

- 插件抽屉 · 立绘:提示词模板那一组下面一行模型状态:「情绪识别模型:已就绪」/「没装 —— 在 AnimaBackend 里运行 `python scripts/download_emotion_model.py`。不装也能用,只是对不上列表的表情不会切图」/ 加载报错原文
- 视觉小说控制台,每个立绘标签的匹配结果:
  - `✓ 微笑`(精确)
  - `≈ 微笑(模型 0.83)`(模型)
  - `… 识别中`
  - `✗ 情绪模型不可用:<原因>,保持上一张`
  - `— 「X」的台词,不切立绘`(NPC)
- 占位框写匹配后的内置表情名

## 测试

后端(pytest):
- `EmotionMatcher` 用假 encoder:挑最高、多个名字取最大、并列取前面、同一文本只编码一次、标签去重
- 接口:用依赖覆盖换成假 matcher 测返回格式;模型目录不存在 → 503 带原因;校验 422;`/status`
- 真模型:目录里有模型才跑(没有就 skip)。「开心」在「高兴 / 生气 / 害怕」里选「高兴」
- 「按立绘表情补齐」:卡没有立绘时按内置列表补;原有测试照样通过
- 内置列表:名字、顺序和 `PRESETS` 一致

前端没有测试框架:匹配和累计规则写成纯函数,验证靠 `npm run build`、`npm run lint` 和浏览器里跑一遍(有立绘的卡、没立绘的卡、模型没装三种)。浏览器实测前先备份 `plugin.*` 设置,别点「恢复默认」。
